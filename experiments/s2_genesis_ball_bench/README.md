# S2：Genesis 全碰撞机器人 + 足球的吞吐与稳定性

`bench.py` 直接用 microduck-rl-genesis 的训练环境（训练模式：DR、推力扰动、指令重采样、跌倒 reset 都开着），由 Genesis 训练的行走 ONNX 驱动。可选项：

- 换成全碰撞机器人 `robot_allcollisions.xml`
- 加入游戏用的球（`ball_game.xml`：100 mm、30 g）。每 2 s 把球重新放到每个机器人前方 9–13 cm，保证持续有碰撞
- 开 / 关自碰撞
- 调整碰撞对上限

运行方式：`./run_matrix.sh`（只用空闲的 HIP 0–3，即 rocm-smi 的 card3/2/0/1）。

## 结论

- MuJoCo 里全碰撞模型也只有 **11 个碰撞几何体**（其余约 70 个是纯视觉的），两个引擎都对 mesh 的凸包做碰撞，碰撞形状一致。换成全碰撞模型几乎不增加开销（-3%）。
- 加球后吞吐下降约 20–33%，4096 个环境下仍有约 63–75k env-steps/s。4 个任务同时跑，数字有 CPU 争用噪声：上限 60 那一组跑的时候并发更少，所以更快。
- **数值稳定**：0 个求解器错误，0 个 NaN，球没有被弹飞（最大 1.7 m/s）。球穿透超过 5 mm 的情况约为百万分之四，最深一次 19 mm（推测是脚踩到球）。全碰撞模型下行走策略的跌倒率没有明显变化。
- **训练成本估算**（rollout 时间 + 约 0.3–0.5 s 的 PPO 更新）：
  - soccer 原作者的规模（1024 × 2000 轮）约 **1 小时**
  - 上游 ball_kick 的规模（4096 × 10k 轮）约 **5–6 小时**
  - 显存不是瓶颈（单卡 32 GB，每个任务大致只用几 GB；rocm-smi 采样在并发时不太准）
